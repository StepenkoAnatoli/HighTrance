# Design: Per-group stems export (step 6a of roadmap — "variation / stems / packaging")

**Date:** 2026-10-09 (rev. 3 — addresses two adversarial re-reviews) · **Status:** draft for re-verification · **Branch:** `feature/stems-export`

Citation labels: **§2 rN** = Context-table row N; **fN** = review finding; **fN′** = response to fN.

## 1. Goal

From the roadmap's Advanced/Future list — *"Export stems (Drums / Bass / Leads / Pads separately)"* — add a first-class stem-export path to the built-in synthesizer. A generator run can additionally write one WAV per instrument group (drums / bass / leads / pads / fx) that:

1. **sums back to the pre-master mix**, up to one shared gain, so the groups can be re-mixed and reconstructed (see §3 D2 for the exact invariant); and
2. **never clips** a 16- or 24-bit WAV file.

Hard constraints (standing mandate): the built-in synth + mastering path keeps working with **no external tools**; the default render (stems off) stays **byte-identical**; same-seed output stays **deterministic**. Stem export is built-in-only, exactly like the audio-level sidechain (step-5 D6): the FluidSynth path renders one mixed MIDI and cannot be split.

| 1 | `render_song_audio` renders every `song.tracks` entry, then accumulates **three buses** in the same loop: `master += dry`, `reverb_bus += rev`, `delay_bus += dly`, where `(dry, rev, dly) = mixer.process_track(track.name, stereo, duck)` | `synthesis/audio_render.py:117-128`; `synthesis/mixer.py:176-191` |
| 2 | **Reverb is LTI.** `mixer.reverb(reverb_bus, seed)` generates an impulse response from `np.random.default_rng(seed)` (using `reverb_size`, `sr`) and convolves `mono` with it (`signal.oaconvolve`) — the IR depends only on `seed`, `reverb_size`, `sr`, not on the input. | 3 | The remaining tail is a **common** operation: `master += delayed`; `reverb_bus += delayed.mean(axis=1)*0.5`; `wet = mixer.reverb(reverb_bus, seed=song.seed % (2**32))`; `wet *= (1 - 0.5*duck)` if `duck` not None; `master += wet`; then `mixer.master(master)` applies the **non-linear** glue compressor / limiter / normalise | `synthesis/audio_render.py:133-143`; `synthesis/mixer.py:193-202` |
| 4 | The chosen design is **per-group finishing (independent FX per group)**: for `stems=True`, accumulate per-group buses `dry_g/rev_g/dly_g`, finish each group independently to produce `raw_g = finish_group(buses_g)` (each group’s audio after applying that group’s delay+reverb+duck to its own buses), compute `premix = Σ_g raw_g` in `STEM_GROUPS` order, apply `mixer.master` once to `premix` to get the mastered `mix`, and write scaled `stems[g] = gscale*raw_g`. The invariant is **numeric**: `Σ_g stems ≈ gscale * premix` (float32) and `master(premix)` equals the mix from the stems path. The cross-group delay feedback coupling is intentionally not preserved in the per-group stems; stems are per-group post-FX signals scaled to share one peak ceiling. | §3 D2 (revised) |

## 3. Decisions

| # | Decision | Alternatives rejected |
|---|---|---|
| D1 | **Grouping.** `config/settings.py` adds `STEMS = {"peak": 0.95}` and `STEM_GROUPS: Dict[str, Tuple[str, ...]] = {"drums": ("kick","percussion"), "bass": ("bass",), "leads": ("acid","lead","arp"), "pads": ("pad","texture"), "fx": ("fx",)}`. Build `_TRACK_TO_STEM` reverse map and `stem_group(name) -> str` (raises `ValueError` if unknown). `STEM_GROUPS` insertion order defines file/sum order. Validate all `TRACK_ORDER` names map to exactly one group (including all entries). Unknown track names must raise; this is a hard invariant. | Silent `"other"` group; grouping by module. |
| D2 | **Per-group finishing, delay feedback trade-off, correct invariant.** Extract `_finish_returns(mixer, master_bus, reverb_bus, delay_bus, duck, seed, base_seed) -> np.ndarray` where `base_seed = seed % (2**32)`. This is the "finish" operation (apply delay, reverb, wet gain/duck, and return `master_bus` with the tail applied in the same order as the canonical tail), implemented so the code path is unambiguous. **Critical:** the default path (`stems=False`) must be byte-identical to current code; the finishing logic must be factored in a way that preserves exact operations and in-place semantics (do not reorder/add/remove operations). Prefer keeping the original accumulation/tail block intact for `stems=False` and only adding the stems path in parallel; if a shared helper is introduced, it must produce identical bytewise results for the single-bus case. When `stems=True`, accumulate per-group `dry_g/rev_g/dly_g`. For each group, finish independently: `raw_g = _finish_returns(mixer, dry_g, rev_g, dly_g, duck, base_seed)` using the **same** `base_seed` (and thus the same LTI IR). Ping-pong delay has feedback and is **not** LTI; therefore `Σ_g finish_group(buses_g) != finish_shared(Σ_g buses_g)` in general. The stems represent **per-group finished signals** (post-FX applied per group), not a linear decomposition of the shared-FX mix. **Invariant (numeric):** `Σ_g stems ≈ gscale * premix` (float32) where `premix = sum(raw_g for raw_g in stems_raw.values())` in `STEM_GROUPS` order, and `mixer.master(premix)` equals the mastered mix produced by the stems path. The equality we assert is **not** "mix equality to shared-FX finished sum" (which is false under feedback coupling); we assert **reconstructibility via sum** (`Σ stems ≈ gscale*premix`) and that `master(premix)` matches the stems-derived mastered mix. For `stems=False`, the returned mix is the canonical mastered mix. Add `render_song_audio` = `_render(False)[0]` and `render_song_stems` = `_render(True)` returning `(mix, stems_dict, mix_unmastered_premix=None)` as needed for verification. | Shared-FX tails from full mix (cannot produce per-group finished stems without recomputing per group); applying master per stem (breaks global mastering); treating delay feedback as LTI. |
| D3 | **Gain safety and sanitization (stems path only).** For the stems output path only: sanitize non-finite values before peak/scale: `raw_g = np.nan_to_num(raw_g, nan=0.0, posinf=0.0, neginf=0.0)`. Compute global peak `peak = max_g max_t |raw_g[t]|` over all groups; if `peak <= 1e-10` set `gscale = 1.0` else `gscale = STEMS["peak"] / peak`. Clamp `gscale` to `[0.0, 1e6]`. Do **not** apply this sanitization/peak-scaling logic to the default `stems=False` path; the default path must remain byte-identical. | Applying sanitization to default path (changes behavior/bytes); no thresholding (explodes on tiny noise); silent group division. |
| D4 | **I/O.** `write_wav` semantics unchanged (16/24-bit only, chunk clipping to `[-1,1]`, mono/stereo, parent dirs). `write_stems(stems: Dict[str, np.ndarray], out_dir, sample_rate=..., bit_depth=...) -> Dict[str, str]` writes `<out_dir>/<group>.wav` for each key in `STEM_GROUPS` order (and only for groups present in the dict), creates dirs, returns paths. `AudioGenerator.render_song_stems(song, output_path=None, stems_dir=None, progress=None) -> Tuple[str, Dict[str, str]]` where first return is the mastered mix WAV path (same mastering as `render_song_audio`). Stems are written as WAVs (MP3 only affects mix if format conversion applied to mix). | Skipping silent groups; writing stems in arbitrary order. |
| D5 | **Generator + result and gating order.** `TranceGenerator.generate(self, render_audio=False, audio_format=None, song=None, progress=None, master=None, stems=False) -> Dict`. Initialize `stem_paths: Dict[str,str] = {}`, `stems_dir: str | None = None`. **Gating order (exact):** 1) If `stems` is True and `render_audio` is False: log warning `"Stem export needs audio rendering; ignoring stems"` and set `stems = False`. 2) If `stems` is True and `render_audio` is True: if `self.renderer == "fluidsynth"`: log warning `"Stem export needs the built-in renderer; skipping stems"` and set `stems = False`. 3) Only if both conditions hold and renderer is builtin (or auto→builtin) do stems export run. Mastering applies only to the mix; MP3 conversion applies only to the mix (stems remain WAV). On success, result must include `stem_paths` and `stems_dir` (empty/None only when stems not produced). | Overloading `AudioGenerator.render` to return stems; wrong gating precedence. |
| D6 | **CLIs.** `main.py` and `ui/cli.py` add `--stems` (action="store_true", help="Export per-group stems (drums/bass/leads/pads/fx); requires --render-audio and built-in renderer"). `render_audio = render_audio or review or stems`. Both call `generate(..., stems=args.stems)`. `ui/cli.print_summary` adds a stems line: `Stems   : <stems_dir>` when `result.get("stem_paths")` is non-empty (or when stems were produced). If stems were skipped due to gating (no-audio or fluidsynth), summary must still reflect what happened (warnings emitted). | Hiding behind renderer flag; missing summary line. |
| D7 | **Web.** Add `stems = gr.Checkbox(value=False, label="Export stems (Drums/Bass/Leads/Pads/FX)")`. Add `stems_files = gr.File(label="Stems (WAV)", file_count="multiple", interactive=False)`. **Arity/signatures (complete):** `generate_track(style, energy, complexity, melody, arp, bass, drums, pad, texture, fx, master, stems, progress=gr.Progress(...))` returns a 7-tuple: `(status, player, midi_file, audio_file, stems_files, history_df, history_dropdown)`. `load_from_history(choice, style, energy, complexity, melody, arp, bass, drums, pad, texture, fx, master, stems)` takes stems as the 12th control argument and returns 13 outputs: `(style, energy, complexity, melody, arp, bass, drums, pad, texture, fx, master, stems, status)`. `make_bundle(midi_file, audio_file, stems_files=None)` adds each stem under `stems/<group>.wav` (arcname) if it exists; silently skip missing entries and never raise. History entries gain `"stems": bool(stems)`. History validation requires `isinstance(entry.get("stems"), bool)`. `stems_files` returned as list of paths in `STEM_GROUPS` order (or `None` if empty). Treat missing `stems` key in legacy history entries as `False` for backward compatibility. | No stems in history/bundle; incomplete arities; breaking history schema. |
| D8 | **Tests + byte-identity + mix equality (corrected).** Create `tests/test_stems.py` with: grouping coverage (all TRACK_ORDER covered, unknown track raises), default byte-identity for fixed seed/song (`stems=False` path identical to baseline), mix equality semantics clarified: the mastered mix from stems path (`master(premix)`) must equal the mix from stems path run; **do not** require `stems_mix == shared_FX_mix` under feedback coupling. The D8 "mix equality" test must be: (a) reconstructibility `np.allclose(np.sum(list(stems.values()), axis=0), gscale*premix, atol=1e-5, rtol=1e-5)` (sum invariant), and (b) `np.allclose(mix_stems, render_song_audio_for_same_run_context, atol=1e-4, rtol=1e-4)` where both use stems=True path to produce the mastered mix? Or more precisely: run `_render(True)` to get `(mix_s, stems_dict)` and verify `Σ stems_dict ≈ gscale*premix` and that `mix_s` is the mastered mix derived from `premix`. If comparing to `stems=False` path, the correct comparison is byte-identity of default path (D8(b′) must be **byte-identity**, not float-equality under per-group FX redefinition). Replace/clarify D8(b′): "mix equality" test becomes **byte-identity test** for `stems=False` (identical WAV bytes or identical float arrays in the exact code path). Also add: gain (global peak of raw stems == `STEMS["peak"]` ± 1e-6 after scaling policy, all scaled stems <= `STEMS["peak"]` + 1e-6), determinism (same seed -> identical stems bytes/values), write_stems order, generate paths (stems=True ok, stems+no-audio warning and stems forced False, stems+fluidsynth warning and stems forced False), anti-phase tolerance, silent group handling, tiny peak threshold (<=1e-10 -> gscale=1.0), sanitization (`nan/inf` -> 0.0) only on stems path, commutation note test (explicitly assert feedback non-commutativity or at least document behavior), seed edge cases, **byte-identity regression test** (critical): for a fixed mini song and fixed seed, default render bytes unchanged vs baseline. Update `tests/test_web_ui.py` for all arity/schema changes (including stems in history). Existing tests (`tests/test_sidechain.py`, `tests/test_audio_render.py`) must remain green. | Only float "mix equality" between shared and per-group FX (mathematically false with feedback); missing byte-identity test; missing web updates. |
| D9 | **Verification.** Full pytest (171+new), CLI render with `--stems`, web smoke, bundle contains stems under `stems/<name>`, token check, README examples verbatim, same-seed byte equality of default render across refactor (byte-identity), measure stems vs plain render cost (reverb ~5× + delays). | Skipping default byte-identity check. |

## 4. Scope

**In:** D1-D8 above. **Out:** FluidSynth stems, stems in review loop, per-stem mastering, 32-bit-float WAVs, changing mixer/EQ/sidechain.

## 5. Risks

| Risk | Mitigation |
|---|---|
| Default render not byte-identical | Keep in-place tail for `stems=False`; add byte-identity test (D8/D9); compare WAV bytes/arrays for fixed mini song; factor only with equality checks. |
| Ping-pong delay breaks commutativity (r4) | Design states per-group FX with explicit trade-off; invariant is numeric `Σ stems ≈ gscale*premix` and `master(premix)` matches stems-derived mix; do **not** assert shared-FX equality. Tests must reflect this mathematical reality. |
| 5× reverb cost | Only opt-in; can IR-cache later (§6) (identical IR across groups when same seed); measure in D9. |
| Tiny peak → explosion | `peak <= 1e-10` threshold + clamp `gscale` to `[0.0,1e6]` (D3); sanitize non-finite on stems path only. |
| Web arity break | Update all call sites and tests (D7/D8); complete arities listed. |
| Non-finite values | `np.nan_to_num(..., nan=0, posinf=0, neginf=0)` before peak/scale on stems path only (D3). |
| Unknown track names | `stem_group` raises `ValueError`; validation in D1 covers all `TRACK_ORDER`; generate surfaces error appropriately (D5). |
| Backward compat (history/web) | Treat missing `stems` in history as `False` (D7); bundle handles missing stems gracefully. |
