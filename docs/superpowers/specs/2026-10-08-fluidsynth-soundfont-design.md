# Design: FluidSynth + SoundFont on Windows (step 2 of roadmap)

**Date:** 2026-10-08 (rev. 2 — after adversarial review, 18 findings closed) · **Status:** revised for re-review · **Branch:** `feature/fluidsynth-soundfont`

## 1. Goal

Make `--renderer fluidsynth` actually produce audio on a stock Windows machine, with a
good General-MIDI SoundFont, and document the optional-audio stack in the README —
built-in synth stays the zero-setup default; FluidSynth becomes a one-time SoundFont
download plus one command.

## 3. Decisions

| # | Decision | Alternatives rejected (and why) |
|---|---|---|
| D1 | **Binary install = official win64 zip** → `%LOCALAPPDATA%\Programs\FluidSynth`, user PATH. README documents this + Linux `apt install fluidsynth`, and says **open a new terminal** after PATH changes. | winget/scoop/choco: no package (evidence above). Machine PATH: needs admin. MSYS2: heavyweight. |
| D2 | **Do not commit the 32 MB `.sf2`.** Commit `soundfonts/README.md` (download URL + SHA-256 checksum + `--soundfont` override note). `.gitignore` gains **`*.sf2`** (covers `soundfonts/` *and* a stray `FluidR3_GM.sf2` in repo root — README:39 historically encouraged that filename). Edit `.gitignore` **append-only outside the credentials block (lines 83-86)**. | Committing: bloats every clone for a re-downloadable asset. `soundfonts/*.sf2` only: leaves the root FluidR3 name unignored. |
| D3 | **Discovery precedence: explicit param → module-relative `soundfonts/` → CWD-relative → Linux FHS.** Module group order: `GeneralUser-GS.sf2`, `FluidR3_GM.sf2`, then other `*.sf2` sorted; module group first so the project's curated font beats an ambient CWD/system font. Implemented via two module-level constants (`SOUNDFONT_DIR`, `SOUNDFONT_CANDIDATES`) read **at call time** so tests can monkeypatch with `tmp_path`. | CWD-first: repo-root CWD makes `soundfonts/FluidR3_GM.sf2` shadow GeneralUser; a stray font in whatever dir the user `cd`'d into beats the project's. Glob-only without pinned names: sorted glob is deterministic, but pinned preference is the real reason (restated honestly). Renaming GeneralUser to `FluidR3_GM.sf2`: dishonest. **Behavior change flagged:** on Linux with system FluidR3 installed, winner changes from system font → repo font (deliberate: project asset wins; documented in README). |
| D4 | **README integration along existing seams:** new **"Audio rendering" section between Usage (ends ~L70) and "Review mode" (L72)**; edit existing L39 (FluidR3 recommendation → GeneralUser + `soundfonts/README.md`), L43, L65 (show `--soundfont` as optional override now that discovery works) instead of duplicating; **timeout caveat goes into the existing "Review mode" section** next to L89-91 with corrected wording: *"on a CPU-only machine every request exceeds the 60 s default and the loop offers retry/quit — raise `REVIEW["llm"]["timeout"]` (e.g. 900) in `config/settings.py` before first use; a full round took ~13 min at 600 s"*. New-section examples are **single-line commands, verified verbatim in PowerShell** (no bash `\` continuations). Also fix `main.py` help text that implies FluidSynth is needed where it isn't (L76-area wording, verified at implementation time). | One merged section (review docs already have a home at L72-91). Bash-style multi-line examples (break in PowerShell — this design targets Windows). Changing the 60 s default here (owner's spec value; flagged, not changed). |
| D5 | **Verification protocol** (all via entry point **`python -m ui.cli`**, pinned seed/length/sample-rate/master; FluidSynth E2E runs **outside pytest**): **(0)** capture pre-change built-in baseline render + SHA-256 **before any code edit** (filenames embed timestamps → compare by content, not name); **(1)** preflight: explicit PATH prepend + `shutil.which("fluidsynth")` non-None (fail loudly, never skip); **(2)** D6-fix render: `--renderer fluidsynth --no-master` → output `exists()`, WAV header 44100/2ch/16-bit, duration differs from built-in baseline's duration signature; **(3)** reference compare: manual `fluidsynth -ni -g 0.7 -F ref -r 44100 soundfonts/GeneralUser-GS.sf2 <midi from run 2>` vs app output — byte-equal expected (same invocation, no mastering); any allowed deviation must be investigated and documented; **(4)** `auto` run → content hash equals baseline from step 0; **(5)** discovery unit tests in new `tests/test_audio_render.py`, `tmp_path` + `monkeypatch`, preserving `synthesis/audio_generator.py` re-exports — enumerated cases: explicit `soundfont_path` param wins over discovery; module-relative find (GeneralUser preferred, `FluidR3_GM.sf2` fallback, other `*.sf2` sorted); CWD-relative fallback when module dir has no font; Linux FHS fallback; nothing anywhere → `None`; call-time constant read (monkeypatch takes effect); **(6)** full suite matches baseline **106 + new tests** (baseline runtime ~304 s); **(7)** `git check-ignore soundfonts/GeneralUser-GS.sf2` OK **and** `git check-ignore "Github Token- 30 days- from 14.9.26.txt"` still OK after the `.gitignore` edit; **(8)** README's new commands run verbatim in PowerShell; **(9)** `python main.py --help` shows the corrected wording and no invented flags after the D4 help-text fix. | "WAV differs from built-in" (doesn't prove which renderer ran, and phantom-success made it meaningless); byte-compare without pinning flags (timestamps/mastering make "the WAV" ambiguous); E2E inside pytest (suite already 5 min; stale-PATH would skip or false-green). |
| D6 | **Fix the render path (BLOCKER fix):** `render_midi_to_wav` drops the `midi2audio` branch and always invokes the FluidSynth binary directly with the proven argument order `[-ni, -g, gain, -F, out, -r, rate, sf2, midi]`, `check=True`, stderr surfaced on failure, and a **postcondition: `output_path` must exist** (raise `RuntimeError` otherwise) — eliminating both the broken invocation and the phantom-success class of bug for this path. `midi2audio` removed from `requirements.txt` (its only use **on the render path** was this call; the `import midi2audio` inside the unused `fluidsynth_ready` property remains as a vestigial, guarded import — its effective behavior on fresh installs becomes accurate-via-`shutil.which`, noted, not touched). | Keep midi2audio with an exists-check fallback: keeps a provably broken dependency alive for no benefit. Fixing `core/generator.py` to stat outputs generally: broader refactor, out of scope (D6's postcondition covers the FluidSynth path; built-in path writes via `write_wav` and is unaffected). |

## 4. Scope

**In:** D1 machine setup *(done)*, D2 gitignore + `soundfonts/README.md`, D3 discovery code + unit tests, D4 README edits (L39/L43/L65, new section, review-section caveat, main.py help wording), D5 verification protocol, **D6 render-path fix + requirements change**, PR.

**Out (explicit decisions):** `main.py` gaining `--renderer/--soundfont` (README uses `python -m ui.cli`, matching existing L65); GUI renderer/soundfont control; fixing/removing unused `fluidsynth_ready` (returns true without a binary check — recorded as a known inaccuracy, cleanup candidate, not touched here); ffmpeg install (owner declined); committing the sf2; changing `REVIEW` defaults (owner's call — README documents the workaround); removing `pyfluidsynth` from requirements (import is wrapped, harmless — same cleanup candidate as `fluidsynth_ready`); A/B listening comparison of built-in vs FluidSynth (owner's ears); sidechain/pedalboard epic (roadmap step 5).

## 5. Risks

| Risk | Mitigation |
|---|---|
| Long-running shell host / IDE has stale PATH → `which("fluidsynth")` = None inside spawned tests | D5.1 preflight with explicit PATH prepend, fail-not-skip; README says "open a **new** terminal"; FluidSynth E2E kept out of pytest |
| D6 changes rendered audio output for `--renderer fluidsynth` users (gain 0.7 now always applied; midi2audio gone) | Previously the path produced *no output at all* on FS 2.6.1 — strictly an improvement; gain matches the pre-existing direct-CLI branch default |
| 32 MB URL rot | Pinned `main` branch URL verified 200 (2026-10-08); SHA-256 checksum published in `soundfonts/README.md`; `--soundfont` manual override documented |
| Byte-compare (D5.3) fails due to WAV header/metadata differences | Investigate before relaxing; tolerance must be justified and documented in the run log, never assumed |
| `.gitignore` edit accidentally disturbs credential patterns | Append-only outside L83-86 + D5.7 re-checks token-file ignore |
