# Design: Web UI history + ZIP bundle (step 4 of roadmap — "cheap wins")

**Date:** 2026-10-08 (rev. 4 — final polish: rev-1 blockers closed; re-review findings r-f1…r-f6 closed; final-review polish f1′…f5′ applied. Approved for implementation — no blockers/majors) · **Status:** approved · **Branch:** `feature/web-history-zip`

Citation labels: **§2 rN** = Context-table row N; **fN** = adversarial-review finding N (rev 1); **rN-fN** = re-review finding N.

## 1. Goal

Two small web-UI additions, per the brainstorm file's "Medium Priority" items:

1. **Generation history** — the last 10 runs (seed + settings + outcome), persisted across restarts, shown in the page, one click loads a row's settings back into the controls.
2. **ZIP bundle download** — MIDI + rendered audio of the latest run in one `.zip`.

Two further brainstorm items are **already delivered and only verified here** (§2 r3, r4): the progress bar (Tkinter: `ui/gui.py:71-110` per-track; web: step-3 D7 `gr.Progress`) and the waveform display (gradio's Audio player renders it by default).

## 3. Decisions

| # | Decision | Alternatives rejected (and why) |
|---|---|---|
| D1 | **Store: `<output_dir>/history.json`** (`output_dir` = the same `"output"` the generator uses, CWD-relative, via a module constant — f10) — a JSON array, **newest first, capped at 10**. Entry fields: `time` (local `YYYY-MM-DD HH:MM:SS`), `style, bpm, length, key, scale, seed, intensity, renderer, format, render_audio, master`, `duration_seconds, generation_time`, `status` (`"OK"` / `"MIDI only"` / `"warnings"` / `"failed"`), `error` (first error line or `null`), `midi`, `audio` (**filenames only**). **Written on real generation attempts only** — length pre-check rejection writes nothing (it is a form error, not a run; f3). The generation path runs in `try/except` and writes in `finally` from an entry variable (all 11 handler inputs are function locals → in scope at both sites; f3). Atomic write: `json.dump` to `.tmp` then `os.replace`. Load: missing/corrupt/short → `[]` or best-effort, **never crashes the UI**. | `sqlite3` (overkill); session-only state (lost on restart — brainstorm says *save*); repo-root file; unlimited; full paths (f8); writing pre-check rejections (f3). |
| D2 | **History UI: a readonly `gr.Dataframe` (display) + a `gr.Dropdown` of the 10 rows + a "Load settings" button.** No `df.select` (f1: readonly can never fire it). The dropdown's `choices` are **plain strings** `"#N 2026-10-08 22:15:03 goa/trance 3.0 140 seed=42"` (#N = 1-based position, newest first, **seed suffixed so second-resolution `time` + identical settings can never collide into byte-identical labels** — f2′) — string-only choice+value kills the per-run Gradio `UserWarning` (r-f3) — and the **generate handler returns a 6-tuple** `(status, player, midi, audio, history_df, dropdown)` where `dropdown` is a `gr.update(choices=…, value=<#1 label>)`: the newest run is both visible and selected, so the dropdown can never drift from the file (r-f1). The Load handler parses the leading `#N`, reads the **full JSON entry by list index** (not df cells — `intensity`/`format`/`render_audio`/`master` have no df columns; f5) and sets **all** controls (style, BPM, length, key, scale, seed, intensity, renderer, format, render, master) + status "Settings loaded from history #N — press Generate". **Shrink between dropdown build and click** (file edited externally / a second tab's run capped the list) → in-handler `⚠` status, no crash; a value that is *not* among the current choices is rejected by the component before the handler ever runs (gradio `Dropdown.preprocess` raises — error toast, unreachable via the normal UI; f1′). Caption under the table: "Files stay on disk in `output/`; the Bundle button covers the current run" (f8). Populated in `build_ui()` from disk (survives restart) — empty file ⇒ dropdown shows "No history yet". | Row-click df (unnatural cell editing; f1); interactive df (editable-looking cells w/ silent discard); per-row table buttons (layout sprawl); auto-loading on dropdown change (silent param change). |
| D3 | **ZIP on demand, no `gr.State`** (f2): a **Bundle** button whose `inputs` are the live `midi_file`/`audio_file` component values (legal inputs; unwrap to `str\|None` — r-f6). Click → build `output/bundles/<midi stem>_bundle.zip` with the MIDI and, when present, the audio (WAV, or MP3 when `format="mp3"` succeeded); MIDI-only → just the MIDI. `outputs=[bundle_download (gr.File), bundle_status (gr.Markdown)]`. Both inputs `None` → "Generate a track first". **The zip build is wrapped in try/except** (deleted file mid-session) → `bundle_status` = "MIDI file no longer on disk", no raise into the event loop — step-3 D4 contract (r-f5). The "audio may be WAV despite format=mp3" case resolves naturally (the component value IS the WAV — f8). | Always-built zip (~30 MB disk/run for a rarely-pressed button — r13); `gr.State` paths (f2); zipping from history rows (D5); loose zips in CWD. |
| D4 | **Waveform and progress: no code change** — both delivered (§2 r3–4), phrased honestly (f11): Tk bar per-track; web overlay advances only during the builtin render phase (compose/fluidsynth/MIDI-only show the static overlay — step-3 spec). | Rebuilding a custom waveform image; overlay behavior change. |
| D5 | **History is a log, not a file manager:** rows show filenames and outcomes; settings-reload is the only interaction; re-download/re-render from rows is **Out** (same seed ⇒ same track via r12, so reload + Generate reproduces old runs). Caption per D2 closes the UX gap (f8). | Per-row download buttons (a log can't guarantee path stability); delete/clear (not asked; cheap later). |
| D6 | **Tests (pytest; store paths monkeypatched to `tmp_path`):** (a) history helpers — cap 10 newest-first, corrupt JSON tolerated, atomic write valid, filenames-only, **dropdown-label uniqueness** (two same-second, same-settings entries differing only in seed produce distinct labels — f2′); (b) zip helper — two-file zip lists both members, midi-only lists one, bundles dir created on demand, **missing-file → friendly status, no raise** (r-f5); (c) load-settings mapping — full control round-trip from a JSON entry (incl. `scale`, seed int, `intensity`/`format`/`render_audio`/`master`), `#N` parse + **out-of-range-via-shrink → `⚠` (called directly on the handler — the component rejects non-choice values before the handler in the live UI, f1′)** — labels built stable newest-first with **string** choices (r-f3), **label-uniqueness assertion** (f2′); (d) handler integration (stubbed generator) — **status matrix asserted**, failed-`errors`-then-null-audio case pinned per matrix, pre-check rejection writes **nothing** (f3), **6-tuple**: grid contains the new row AND the dropdown update's choices/`value` point at the new run (r-f1), mp3-requested stores the actual WAV filename (f8); (e) **update the four step-3 tests to unpack the 6-tuple** (f4), other tests untouched; (f) `build_ui()` returns `gr.Blocks` incl. the new components. | No tests; real-`output/` writes; testing the dead `df.select` mechanism (f1). |
| D7 | **Verification protocol:** (0) full `pytest` green (130 + new); (1) browser E2E with **real clicks and label↔values assertions**: launch `python main.py --web` → MIDI-only run → history row appears **and the dropdown's first label contains that run** → change some controls → **history dropdown + Load button** → **the repopulated control values equal the labelled entry's values** (not merely "changed" — r-f2) → full render → Bundle → download zip → `zipfile` lists both members; (2) restart the server → table AND dropdown persist; (3) hand-corrupt `output/history.json` → app loads with empty history; (4) `main.py`/`ui/gui.py`/`ui/cli.py` no diff; (5) README examples verbatim; (6) screenshots for the owner. | HTTP-only smoke (misses the interaction; f1's failure mode was exactly this); open-ended "DOM repopulates" check (r-f2); skipping corrupt-file (startup-brick failure). |
| D8 | **README:** the Web UI section gains two sentences — history (last 10 runs in `output/history.json`; dropdown + Load restores a run's settings; files stay on disk) and the Bundle button (MIDI + audio in one zip). Nothing else moves. | A new doc page; documenting Out items. |

## Status matrix (normative; pinned by D6(d))

| Condition | `status` |
|---|---|
| `render_audio=False` | `MIDI only` |
| `render_audio=True`, `audio_path` present, `errors` empty | `OK` |
| `render_audio=True`, `audio_path` present, `errors` non-empty (mastering failed → raw WAV kept; mp3 requested but ffmpeg missing → WAV kept) | `warnings` |
| `render_audio=True`, `audio_path` None, `errors` non-empty (render died) | `failed` (`error` = first line) |
| `render_audio=True`, `audio_path` None, `errors` empty | **unreachable with the real generator** (a render failure always appends to `errors` — r6); the handler's defensive `⚠️ "Audio was not rendered"` branch (web.py:91-92) is harmonized to keep enum/text consistent: entry `status="failed"`, `error="Audio was not rendered"` — pinned in D6(d) so it can never diverge (r-f4) |
| exception in handler | `failed` (`error` = `str(exception)`) |
| length pre-check rejected | **no entry written** |

## 4. Scope

**In:** D1 store, D2 history UI + reload, D3 bundle zip, D4 discharges, D5 log semantics, D6 tests, D7 verification, D8 README, PR.

**Out (explicit):** musical variation / arrangement work (separate musical effort); CLI/Tkinter history; clear-history button; per-row re-download/re-render; stats/analytics; multi-user guarantees beyond queue serialization; waveform/progress rework (already delivered); `.gitignore` changes (r5: none); sidechain/pedalboard (step 5); stems/variation/packaging (step 6). Also **Out now but re-openable:** a `df.select`-based row interaction (blocked by gradio r11 until readonly-select works; this rev uses dropdown + Load).

## 5. Risks

| Risk | Mitigation |
|---|---|
| Dropdown drifts from the history file → clicking a stale index loads the wrong run | The dropdown is a **generate-handler output** refreshed to the new run on every run (r-f1); load parses `#N` at click time and reads the JSON entry by current list index; shrink → in-handler `⚠`, never a wrong load (non-choice values are component-rejected — f1′); D6(d) + D7(1)/D7(2) pin both the refresh and the persistence |
| Startup with a corrupt history file bricks the page | D1 load-tolerates everything; D6(a) + D7(3) |
| 30 MB zips accumulate | Same `<stem>_bundle.zip` overwritten per run; `output/` is the artifact dir; documented |
| Handler arity regression slips past step-3 tests | The four affected tests are updated to unpack 6 in the same PR and named (§2 r8, D6(e)) — a 6-tuple handler with a 4-unpack test fails loudly |
| Bundle handler raises on a file deleted between runs | D3 try/except → status note; D6(b) missing-file case (r-f5) |
| Per-run Dropdown `UserWarning` from non-string value | D2 string-only choices, `value` = one of the choice strings; D6(c) asserts (r-f3) |
| Two tabs writing history concurrently | Queue serializes handler runs (r7); atomic replace prevents torn files; last-writer-wins acceptable for a log |
